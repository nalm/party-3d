# 정당 3축 탐색기 (party-3d)

경제 × 사회·문화 × 민주주의 규범 **3축 독립 공간**에서 각국 정당의 위치를 회전·확대하며 탐색하는 정적 웹앱.
오마이뉴스 편집국 및 대외 공개용.

> ## ⚠ 현재 상태 — 규범축·한국 좌표 인용 금지
>
> **유럽 18개 레코드의 경제·사회문화 축은 CHES 실측값이다** (1999–2024 트렌드 파일 V2, 2026-07-30 교체 — 추출 스크립트 [`scripts/apply-ches.mjs`](scripts/apply-ches.mjs), 매칭 근거 [`data/crosswalk.json`](data/crosswalk.json)).
> **그러나 민주주의 규범축 전체와 한국 정당의 모든 좌표는 여전히 추정치다.** 규범축은 V-Party 원본이 아닌 2차 문헌 인용값이고, 한국 정당(`kr-ppp-2025` · `kr-dp-2025`)의 규범축은 `docs/coding-rubric.md`의 Z-1~Z-4 판정을 **거치지 않은 잠정값**이며 증거 로그가 없다.
> 공개 조건과 결정 이력은 [CLAUDE.md](CLAUDE.md)의 「공개 조건」 절에 있다.

---

## 왜 3축인가

'진보 대 보수' 단일 축은 세 가지 한계가 있다.

1. **국가 간 의미 비대칭.** 미국의 `liberal`은 좌파, 유럽의 `liberal`은 시장자유주의(경제적 우파)다.
2. **한국에서는 계급·재분배 축이 아니다.** 한국의 '진보/보수'는 실제로 민주화운동 계보·대북정책·지역주의의 축약어다.
3. **가장 중요한 정보를 놓친다.** 정당의 이념 위치와, 그 정당이 민주주의 제도를 준수하는지는 별개 문제다.

이 프레임은 정당을 3개의 **독립** 축에 배치하고, 조직 형태와 포퓰리즘은 축이 아닌 태그로 병기한다.

| | 축 | 척도 | 성격 |
|---|---|---|---|
| X | 경제 | 0–10 (재분배 ↔ 시장) | 연속 스펙트럼 |
| Y | 사회·문화 (GAL–TAN) | 0–10 (자유·개방 ↔ 권위·전통) | 연속 스펙트럼 |
| Z | 민주주의 규범 | **0–1** (다원주의 ↔ 반다원주의) | **임계선** |

**세 축의 척도는 서로 다르며 정규화하지 않는다.** 화면 좌표로 매핑할 때만 각각 독립적으로 스케일한다. Z를 X·Y와 같은 스케일로 합치면 Z의 임계선 성격이 사라진다.

핵심 설계 결정은 **포퓰리즘을 규범축에서 분리**한 것이다. Medzihorsky & Lindberg(2023)의 발견 자체가 "포퓰리즘이 아니라 반다원주의가 민주주의 훼손의 예측자"라는 것이므로, 둘을 한 축에 묶으면 그 발견을 무효화한다.

## 이 앱으로 무엇이 보이는가

궤적 기능이 이 앱의 최대 강점이다. 정적 스냅숏에서는 완전히 사라지는 정보다.

**상반된 이동들이 데이터에 들어 있다** (경제·사회문화는 CHES 실측, 규범은 추정치).

| 정당 | 경제 (실측) | 사회·문화 (실측) | 규범 (추정) | 읽는 법 |
|---|---|---|---|---|
| 헝가리 Fidesz 2010→2019 | 3.41 → 3.73 (+0.32) | 7.24 → 9.20 (**+1.96**) | 0.40 → 0.88 (**+0.48**) | 경제는 고정. 문화 우경화보다 **규범 붕괴가 척도 대비 더 크다** (+20% vs +48%) |
| 프랑스 RN 2010→2019 | 6.50 → 6.88 (+0.38) | 9.56 → 8.13 (**−1.43**) | 0.70 → 0.75 (+0.05) | 경제·규범은 고정, **문화가 온건화** — 이미지 세탁(dédiabolisation)과 부합 |
| 폴란드 PiS 2019 | **2.95** | 9.14 | 0.75 (추정) | 급진우파인데 경제는 뚜렷한 좌측 — **급진우파 ≠ 경제우파**의 실측 사례 |

**시드 추정치와 실측의 괴리 자체가 발견이었다.** 시드는 Fidesz·PiS를 경제 중도우파(6.3, 5.5)로, RN을 "경제 좌클릭"(4.5)으로 놓았지만 CHES 전문가들은 Fidesz·PiS를 좌측(3.4, 3.0)에, RN을 우측(6.88)에 배치한다. 상세는 `data/parties.json`의 `_meta.seed_discrepancy` 참조.

또 하나. **스페인 Vox(규범 0.55)와 이탈리아 FdI(0.45)는 규범축 차이가 0.10뿐인데 절단점 0.50을 사이에 두고 구간이 갈린다.** 절단점 슬라이더를 조금만 움직이면 두 정당이 같은 구간으로 합쳐진다 — 절단점이 문헌 근거 없는 제안값이라는 사실을 손으로 확인할 수 있다.

## 사용법

- **3D 뷰** — 드래그로 회전, 휠로 확대. 각 점에서 바닥면으로 내린 **드롭라인**이 깊이를 읽는 단서다. 바닥 격자는 깊이 참조용이며 아무 의미도 없다.
- **2D 뷰** — 경제 × 사회·문화 산점도. 규범축은 색과 도형으로 이중 인코딩된다. **보도·인쇄용 정본이다.**
- **점 클릭** — 데이터셋 · 판 · 변수명 · 연도 · 척도 범위가 상세 패널에 표시된다. 출처 표시는 선택 사항이 아니다.
- **PNG 내보내기** — 2D 기준으로 저장하며, 경고와 출처가 **이미지 안에** 새겨진다. 이미지는 캡션 없이 단독 유통되므로 화면 배너만으로는 부족하다.

### 인코딩

| 규범 구간 | 색 | 도형 |
|---|---|---|
| 다원주의 0.00–0.30 | `#4a9eff` | 구 / 원 |
| 경계 0.30–0.50 | `#eda100` | 8면체 / 마름모 |
| 반다원주의 0.50–1.00 | `#d03b3b` | 4면체 / 삼각형 |

**색만으로 범주를 구분하지 않는다.** 색과 도형을 항상 함께 쓴다. 점선 윤곽·반투명은 추정치를 뜻한다.

## 캐비엇 (인용 시 병기 권장)

1. **전문가 조사의 규범적 편향.** CHES · GPS · V-Party는 전문가 코딩이다. 지표 상승이 실제 행태 변화인지 코더가 인식하는 정치적 온도의 변화인지 완전히 분리하기 어렵다.
2. **강령과 행태의 괴리.** MARPOR는 강령 기반이므로 실제 집권 행태와 다를 수 있다.
3. **낙인 도구화 위험.** '극우' · '반다원주의' 같은 라벨은 정치적 무기로 오용되기 쉽다. 반드시 **어떤 지표의 어떤 요소**인지 명시하고, 단정 대신 조건부 서술을 유지한다. 특히 국민의힘에 대해서는 명세 12.1절의 권장 서술을 따를 것 — **UI의 구간 라벨만 읽고 "반다원주의 정당"이라고 쓰면 명세 위반이다.**
4. **서구 프레임의 기계적 이식.** 한국에서는 대북·지역·세대·젠더 균열이 서구 축과 다르게 작동한다. 프레임은 출발점이지 최종 판정이 아니다.
5. **척도 이질성.** X·Y는 0–10, Z는 0–1이다. 정규화해 하나의 스케일로 합치지 말 것.
6. **동적 변화.** 반드시 연도를 표기하고 시계열로 추적한다.
7. **절단점의 임의성.** 규범 구간 0.30 / 0.50은 명세의 제안값이며 문헌 근거가 없다. 사용 시 절단점을 명시해야 한다.

| V-Party (V-Dem) v1 | 예테보리대 | `v2xpa_antiplural`, `v2xpa_popul`, `v2pariglef` | 169개국 1,955개 정당, 1970–2019 |

**커버리지 공백:** CHES에 한국·일본·미국이 없다. 한국 정당 데이터는 자체 전문가 서베이 또는 강령·성명 코딩으로 생산해야 하며, 이것이 이 프로젝트의 최대 병목이다.

## 배포

```bash
npm run deploy
```

`vite.config.js`의 `base`가 저장소 이름(`/party-3d/`)과 일치해야 한다. 불일치하면 GitHub Pages에서 에셋 404가 난다.

**배포 전 확인할 것.** 좌표가 전부 추정치인 동안은 다음 세 조건을 모두 만족해야 공개한다 — 화면 상단 고정 경고, PNG 이미지 내 경고 각인, `<meta name="robots" content="noindex">`. 세 조건은 현재 구현되어 있다. 자세한 결정 이력은 [CLAUDE.md](CLAUDE.md) 참조.

## 스택

Three.js (`OrbitControls`, `CSS2DRenderer`) · Vite · 바닐라 JS (ES modules). 상태관리 라이브러리와 UI 프레임워크는 쓰지 않는다.

라벨은 `CSS2DRenderer`로 HTML 오버레이 처리한다. 텍스처·SDF 폰트 방식은 한글 글리프 때문에 번거롭고, HTML 라벨이면 브라우저 폰트가 한글을 그대로 처리해 선명하다.
