# Claude Code 단계별 작업 지시문

> **⚠ 2026-07-30 데이터 교체 후 이 문서의 좌표 수치는 낡았다.** 1~6단계 완료 후 econ·cultural이 CHES 실측으로 교체되어, 본문 완료 조건의 수치(fr-rn 경제 4.5, Fidesz 경제 6.3→6.0, 점 18개 등)는 더 이상 현재 데이터와 일치하지 않는다. 이 문서는 작업 이력으로만 남긴다. 현재 값은 `data/parties.json`이 정본.

각 단계를 **그대로 복사해 붙여넣는다.** 한 번에 여러 단계를 시키지 말 것.
Three.js는 카메라·스케일 문제가 초반에 자주 나므로, 점이 보이는 상태를 먼저 확정해야 이후 디버깅이 쉽다.

각 단계는 완료 조건을 만족한 뒤 다음으로 넘어간다. 완료 조건이 안 나오면 다음 단계로 가지 말고 그 단계에서 고친다.

## 1단계 — 스캐폴딩과 3D 공간

```
CLAUDE.md와 docs/framework-spec.md를 읽었다는 전제로 1단계만 구현해줘.

목표: Vite + Three.js 프로젝트를 세우고, 3축 공간의 골격만 화면에 띄운다.
데이터는 아직 읽지 않는다.

구현할 것
- Vite 프로젝트 초기화, base는 '/party-3d/'
- 와이어프레임 정육면체 (구체 금지)
- 세 축을 큐브 중심을 지나는 선으로. 각 축은 양방향이며 양극 모두 라벨을 가진다
  X 경제: 재분배·국가 개입 ↔ 시장·민영화  (#2a78d6)
  Y 사회·문화: GAL 자유·개방 ↔ TAN 권위·전통  (#1baf7a)
  Z 민주주의 규범: 다원주의 ↔ 반다원주의  (#eb6834)
- 축 눈금. X·Y는 0-10, Z는 0-1 척도임을 반영할 것. 정규화하지 말고
  각 축을 독립적으로 화면 좌표에 매핑한다
- X-Z 평면에 옅은 격자. "깊이 참조용, 의미 없음" 캡션을 화면에 표시
- OrbitControls로 회전·확대·팬
- 라벨은 CSS2DRenderer로 HTML 오버레이 처리 (한글 때문에 텍스처 방식 금지)
- 축 길이·점 크기·카메라 초기 위치 등 수치는 전부 src/config.js로

완료 조건
- npm run dev로 열면 큐브와 세 축이 보인다
- 마우스로 회전·확대가 된다
- 여섯 개 극 라벨이 한글로 선명하게 보이고, 회전해도 읽을 수 있다
- 콘솔 에러 없음

구현 후 완료 조건을 하나씩 확인해서 알려줘.
```

## 2단계 — 데이터와 점

```
2단계를 구현해줘.

목표: data/parties.json을 읽어 정당을 점으로 렌더링한다.

구현할 것
- data/parties.json 로딩. 구조는 { "_meta": {...}, "parties": [...] }
- 로딩 직후 검증하고 위반 시 콘솔 경고
  · 필수 필드 존재
  · v가 scale 범위 안에 있는지
  · norms.band가 v와 일치하는지
  · party_key 중복 연도가 없는지
- 점 배치: econ → X, cultural → Y, norms → Z. 각 축 독립 스케일
- 규범 구간별 색·도형 인코딩 (색만으로 구분 금지)
  다원주의 0.00-0.30  #4a9eff  구
  경계     0.30-0.50  #eda100  8면체
  반다원주의 0.50-1.00 #d03b3b  4면체
- 구간 절단점은 config.js에 두고 하드코딩하지 말 것
- 각 점에서 X-Z 평면까지 드롭 라인. 이게 없으면 깊이 판독이 안 된다
- estimated: true인 좌표는 시각적으로 구분 (반투명 또는 점선 윤곽)
- 현재 시드는 좌표 전부가 추정치이므로 상시 경고 배너를 화면에 표시

완료 조건
- 18개 점이 보인다
- 구간별로 색과 도형이 다르다
- 드롭 라인이 보이고, 회전하면 깊이가 읽힌다
- 경고 배너가 보인다
- 검증 경고가 콘솔에 없다

배치 검증 사례 (이 두 개가 제대로 보이면 인코딩이 작동하는 것)
- fr-rn-2019는 경제 4.5에 있다. 급진우파가 경제적 우파가 아닌 사례
- it-fdi-2019는 문화축 8.7로 극단이지만 규범축 0.45로 경계 구간이다.
  이념축과 규범축이 분리된다는 것을 보여준다
```

## 3단계 — 선택과 출처 표시

```
3단계를 구현해줘.

목표: 점을 선택해 상세 정보와 출처를 확인할 수 있게 한다.

구현할 것
- 호버 시 label_short만 표시. 상시 전체 라벨 표시 금지 (겹쳐서 못 읽는다)
- 클릭 시 선택 상태. 선택된 점은 라벨 유지 + 강조
- 상세 패널에 표시할 것
  · name_ko, name_local, country, year
  · family, intl_affiliation
  · 세 축의 값 + 척도 범위 + src + estimated 여부
  · norms.band 라벨
  · populism_tag, foreign_tag
  · org (institutionalization / personalization / type)
  · 각 지표의 note가 있으면 함께
  · cultural.sub가 있으면 하위 3지표 내역과 가중치 (한국 정당 대비)
- 출처 표시는 필수다. 데이터셋·판·변수명·연도·척도 범위가 다 나와야 한다
- 빈 곳 클릭하면 선택 해제

완료 조건
- 아무 점이나 클릭하면 출처가 보인다
- hu-fidesz-2019를 클릭하면 norms의 note("Medzihorsky & Lindberg 인용값")가 보인다
- 호버만으로는 라벨 하나만 뜬다
```

```
- 규범 구간 절단점 조절 슬라이더 (config 기본값 0.30 / 0.50).

완료 조건
- 국가 필터로 DE만 남기면 5개 점만 보인다
- "경제 × 문화 정면"을 누르면 앞서 만든 2D 산점도와 같은 구도가 된다
- 절단점 슬라이더를 움직이면 uk-con-2019(0.35)의 색이 바뀐다
```

```
5단계를 구현해줘. 이 앱의 핵심 기능이다.

  수치로 표시된다. 즉 "규범축만 움직였다"가 읽힌다
- "규범 정면" 프리셋에서 이 이동이 가장 명확하게 보인다
```

## 자주 걸릴 지점

**점이 안 보인다 (1~2단계)**
카메라 거리와 축 스케일 불일치가 대부분이다. 축 길이를 먼저 고정하고 카메라를 맞춘다. `config.js`에 값이 모여 있으면 조정이 빠르다.

**한글 라벨이 깨진다**
텍스처·SDF 폰트 방식을 쓴 경우다. `CSS2DRenderer`로 바꾼다.

**규범축 색과 경제축 색이 헷갈린다**
**2026-07-30 해소.** 실제로 헷갈렸다 — 1~2단계 구현 후 프레임버퍼 픽셀 검사에서 두 색이 분리되지 않았다. 다원주의 구간을 `#4a9eff`로 밝히고 경제축은 `#2a78d6`으로 남겼다. 재질 구분(축은 불투명 라인, 점은 광택 있는 입체)도 함께 유지한다.

**GitHub Pages에서 에셋 404**
`vite.config.js`의 `base`가 저장소 이름과 다르다. `/party-3d/` 형식이며 앞뒤 슬래시가 다 필요하다.
